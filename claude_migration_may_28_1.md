# Bikershades Migration — What We Built & What I Learned (May 28, 2026)

---

## What We Built

### `fetch_products.py`
Fetches all products from the WooCommerce Store API using pagination and saves them to `products.json`. Stops automatically when the API returns an empty page.

**Result:** 647 products saved across 7 pages.

### `fetch_variations.py`
Fetches full variation data for every variation ID found in `products.json`. Saves to `variations.json` keyed by parent product ID.

**Result:** 6,064 variations across 486 variable products.

Key design decisions in this script:
- Checkpoints after every individual variation — if it crashes mid-parent, it resumes exactly where it left off
- On resume, compares which variation IDs are already saved per parent and only fetches the missing ones
- Safe to kill and rerun at any point without losing progress

## What I Learned

### APIs & Pagination
- APIs limit how many items they return per request (`per_page`) to protect server performance
- `per_page=100` doesn't mean the website shows 100 items — it's just how many the API sends back per network call
- You paginate by incrementing `page` until the API returns an empty array
- The same 647 products, whether fetched as `per_page=100` or `per_page=10`, are identical — just split across more requests

### WooCommerce Product Types
- **Simple** — one SKU, no variants
- **Variable** — has color/option variants, each with their own SKU, images, price, and stock
- **Prescription** — behaves like simple
- Pagination only returns parent products — variations are excluded by design to keep the catalog clean
- Variations are fetched individually via `/products/{variation_id}`, same endpoint as a regular product

### Product Data Shape
- **Prices** are stored as strings in cents — `"1999"` = $19.99
- **`on_sale`** is a WooCommerce flag but only meaningful if `sale_price < regular_price`
- **`stock_status`** is null on all products — real stock info is in `is_in_stock` and `stock_availability.text`
- **`tags` and `brands`** are effectively unused (4/647 products have tags, 0 have brands)
- **Currency fields** are all redundant — everything is USD, frontend hardcodes formatting
- **`_links`** is API metadata pointing back to WordPress — useless after migration

### Images
- Each product has an array of images with multiple sizes (`srcset`, `thumbnail`, etc.) — all generated by WordPress from one original
- Only the original `src` needs to be saved — your CDN/storage handles resizing
- Product descriptions contain embedded `<img>` tags (sizing diagrams, head size charts) that must also be downloaded and rehosted, not just the `product.images[]` array

### Slugs & URLs
- A slug is a URL-safe version of a name — lowercase, spaces replaced with dashes (e.g. `"Backspin Sport Sunglasses"` → `"backspin-sport-sunglasses"`)
- Used in product page URLs instead of numeric IDs — human-readable and SEO-friendly
- Old WordPress `permalink` values should be kept for setting up 301 redirects

### 301 Redirects
- A 301 is a "permanent redirect" — tells browsers and Google the page has moved forever
- The browser never renders the old URL, it silently forwards the user to the new one
- Google transfers SEO ranking from the old URL to the new one over time
- Set up in Next.js via `next.config.js`, or in `vercel.json`, or Nginx config

### SKUs
- Stock Keeping Unit — a unique identifier a business assigns to each product variant for inventory tracking
- Made up by the store owner, no universal format
- Used for warehouse management, connecting systems, and reordering from suppliers

### Variations & Color Swatches
- Variable products have `attributes[].terms[]` — each term is a color option with a `name` and `slug`
- These drive the color swatches on the product page
- When a user clicks a color, the slug matches to a variation, which has its own specific image, price, and stock
- Each variation has a `parent` field pointing back to its parent product ID — the link exists on both sides

### Data Cleanup Decisions
- `short_description` HTML should be parsed into a clean array of bullet point strings
- `description` HTML should be kept raw but with image URLs swapped after rehosting
- Weight and dimensions come as strings — convert to numbers in reshape
- The sale page on the site is manually curated, not an automatic filter of all `on_sale` products
